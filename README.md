# 🧊 Умный холодильник — MVP

Веб-приложение для учёта продуктов, автоматического прогноза срока годности и подбора рецептов из того, что нужно съесть первым — с настоящей синхронизацией между членами семьи через Supabase.

## Файлы

- `index.html` — разметка, Tailwind/шрифты/иконки, экраны входа и семьи
- `styles.css` — палитра (navy + cognac + bone), шрифты, tilt-эффект карточек, анимации
- `config.js` — сюда вы вставляете свои ключи Supabase, здесь же `DELIVERY_CONFIG`
- `state.js` — общее изменяемое состояние (текущий пользователь, семья, список продуктов…)
- `utils.js` — мелкие DOM-хелперы: `escapeHtml`, `formatQty`, tilt-эффект, мелкие модалки, `withBusy` (блокировка кнопки на время запроса)
- `categories.js` — категории продуктов и расчёт срока годности/статуса свежести
- `auth.js` — вход по email/Google, восстановление пароля, вход/создание семьи, presence (кто сейчас онлайн)
- `products.js` — CRUD продуктов, регулярные покупки, рендер холодильника и статистики, уведомления об истекающих продуктах
- `history.js` — лог событий (добавлено/съедено/выброшено) и вкладка «История»
- `recipes.js` — подбор рецептов (локальная база + запрос к Spoonacular через Edge Function), избранное
- `delivery.js` — заглушка кнопки «Заказать ещё» под будущего партнёра доставки
- `main.js` — точка входа: создаёт клиента Supabase, включает остальные модули, навигация между вкладками
- `supabase-schema.sql` — SQL-схема базы данных (таблицы, права доступа, realtime)
- `supabase/functions/recipes/index.ts` — серверная функция-прокси к Spoonacular API (ключ хранится только тут)

Стек: HTML + Tailwind CSS (CDN) + чистый JavaScript (ES-модули, `<script type="module">`) + Supabase (Postgres + Auth + Realtime + Edge Functions). Сборка не требуется — просто открываете `index.html`, модули подключаются напрямую через `import`.

---

## Supabase обязателен

Демо-режима (данные в `localStorage` без входа) больше нет — приложение всегда работает через настоящую базу данных, чтобы холодильник и список регулярных покупок были одинаковыми у всех членов семьи, на любом устройстве. Без настроенного `config.js` приложение покажет баннер с ошибкой подключения вместо экрана входа.

## Как включить синхронизацию (10–15 минут, бесплатно)

1. **Создайте проект Supabase**
   Зайдите на [supabase.com](https://supabase.com) → зарегистрируйтесь → New Project (бесплатного тарифа достаточно).

2. **Примените схему базы данных**
   В панели проекта откройте **SQL Editor → New query**, вставьте содержимое файла `supabase-schema.sql` и нажмите **Run**. Это создаст таблицы `households`, `products`, `household_members`, `product_events`, `regulars`, включит RLS с реальной изоляцией по семьям и realtime-обновления.
   > Уже выполняли более раннюю версию этого файла? Не пересоздавайте всё — выполните только блок «Дополнение v5» в конце файла (таблица `regulars` — без неё список регулярных покупок не появится у остальных членов семьи).

3. **Проверьте вход по Email**
   **Authentication → Providers → Email** — обычно уже включён. По умолчанию Supabase требует подтверждение почты по ссылке; при желании это можно отключить там же (Confirm email → Disable), тогда регистрация будет сразу пускать в приложение без письма.

4. **Включите вход через Google**
   1. В [Google Cloud Console](https://console.cloud.google.com/apis/credentials) создайте **OAuth client ID** типа Web application.
   2. В **Authorized redirect URIs** укажите адрес вида `https://<ваш-проект>.supabase.co/auth/v1/callback` (его подскажет сама Supabase на следующем шаге).
   3. Скопируйте `Client ID` и `Client Secret`.
   4. В Supabase: **Authentication → Providers → Google → Enable**, вставьте эти значения, сохраните.

5. **Укажите адрес сайта**
   **Authentication → URL Configuration**: в `Site URL` и `Redirect URLs` укажите адрес, по которому будет открываться сайт (например, `https://<username>.github.io/<repo>/`). Без этого шага вход через Google и ссылки восстановления пароля будут вести не туда.

6. **Скопируйте ключи подключения**
   В **Project Settings → API** найдите:
   - `Project URL`
   - `anon public` ключ

7. **Вставьте их в `config.js`**
   ```js
   export const SUPABASE_CONFIG = {
     url: "https://xxxxxxxxxxxx.supabase.co",
     anonKey: "eyJhbGciOi..."
   };
   ```

8. **Откройте `index.html` (или задеплойте на GitHub Pages)**
   При первом запуске приложение попросит войти — по email+паролю (регистрация тут же, на той же форме) или через Google. После входа, если человек ещё не состоит ни в одной семье, ему предложат создать семью (сгенерируется код) или присоединиться по коду, который прислал другой член семьи. Дальше — просто пользуйтесь: добавления и удаления продуктов, регулярные покупки появляются у всех участников в реальном времени, а в шапке видно, кто сейчас онлайн. Кнопка выхода — иконка в шапке рядом с аватарками участников.

**О безопасности:** доступ держится на настоящей учётной записи человека, а не на знании кода семьи или анонимной сессии браузера. Данные изолированы на уровне базы через RLS: Postgres проверяет, что запрашивающий пользователь действительно состоит в `household_members` нужной семьи, прежде чем отдать хоть одну строку. Код семьи остаётся способом *присоединиться* (через `join_household`), но сам по себе прочитать чужие продукты не даёт — нужно явно вступить в семью под своим аккаунтом.

`config.js` с `anon`-ключом можно спокойно коммитить в git — он для этого и предназначен, а вся защита обеспечивается описанными выше правилами в базе, а не секретностью ключа.

## Как подключить настоящую базу рецептов (Spoonacular)

Без этого шага раздел «Что приготовить?» использует небольшую локальную подборку из `recipes.js` (10 рецептов, зашиты в код). Чтобы вместо неё подбирались рецепты из настоящей базы Spoonacular (365 000+ рецептов, с фото, временем готовки и шагами) — нужен свой API-ключ и один раз задеплоенная серверная функция.

**Почему нельзя просто вписать ключ в JS-модули:** сайт — статика без своего сервера, а весь JS выполняется в браузере каждого посетителя. Любой ключ, вставленный туда напрямую, будет виден в devtools, и им сможет пользоваться кто угодно за ваш счёт. Поэтому запрос к Spoonacular идёт через Supabase Edge Function (`supabase/functions/recipes`) — там ключ хранится как серверный секрет и в браузер не попадает.

1. **Получите ключ Spoonacular**
   Зарегистрируйтесь на [spoonacular.com/food-api](https://spoonacular.com/food-api) → бесплатный план даёт около 150 запросов в день, этого достаточно для личного/семейного использования.

2. **Установите Supabase CLI** (один раз)
   ```bash
   npm install -g supabase
   ```

3. **Залогиньтесь и привяжите CLI к своему проекту**
   ```bash
   supabase login
   supabase link --project-ref <ваш-project-ref>   # найдёте в Project Settings → General
   ```

4. **Задеплойте функцию и сохраните ключ как секрет**
   ```bash
   supabase functions deploy recipes
   supabase secrets set SPOONACULAR_API_KEY=ваш_ключ_с_spoonacular.com
   ```

5. **Готово** — ничего в `config.js` менять не нужно. Приложение само обращается к функции `recipes` через уже настроенный Supabase-клиент. Если функция не задеплоена или ключ не задан, приложение тихо переключится на локальную подборку рецептов и покажет это в шапке модалки «Что приготовить?» — сайт не сломается.

**Ограничения бесплатного тарифа Spoonacular:** около 150 очков в день (один поиск ≈ 1–2 очка, один просмотр шагов рецепта ≈ 1 очко) и запрет хранить полученные данные дольше часа — наша функция ничего не кэширует и не сохраняет, каждый запрос идёт напрямую в Spoonacular, так что это условие соблюдается автоматически.

## Что уже реализовано

1. **Виртуальный холодильник** — список продуктов с цветовой индикацией (🟢/🟡/🔴) по оставшимся дням.
2. **Добавление продукта** — название + категория, срок годности считается автоматически (`categories.js`, объект `CATEGORIES`), либо вручную — см. «Кастомный срок годности» ниже. Кнопка «Добавить» блокируется на время запроса к Supabase, так что двойной клик не создаёт дубль.
3. **Настоящая авторизация** — вход по email+паролю или через Google (Supabase Auth), с подтверждением почты и восстановлением пароля.
4. **Семейный доступ** — реальная синхронизация через Supabase: код семьи для присоединения, участники онлайн в реальном времени, общий список регулярных покупок (таблица `regulars` — видна всем членам семьи, а не только в браузере, где её завели).
5. **«Что приготовить?»** — подбирает рецепты из настоящей базы Spoonacular по продуктам, которые вот-вот испортятся (с фото и шагами приготовления), либо из локальной резервной подборки, если Spoonacular не подключён. Доступно и для всего списка (кнопка внизу), и для одного конкретного товара (кнопка «Приготовить» на карточке).
6. **Кастомный срок годности** — можно задать точную дату истечения вручную при добавлении продукта (кнопка «Указать срок вручную») или позже — тапом по бейджу свежести на карточке. Кнопки «Удалить» (съедено/выброшено) и «Сохранить срок» тоже блокируются на время запроса — без повторных срабатываний при двойном клике.
7. **История** — отдельная вкладка «История» показывает таймлайн: что добавили, что съели, что выбросили, с датой и именем члена семьи. При удалении продукта из холодильника приложение спрашивает — съеден он или выброшен — и запоминает это.
8. **«Заказать ещё» (заглушка под доставку)** — на карточках товаров, которым скоро истекает срок, есть кнопка «Заказать ещё» рядом с «Приготовить». Партнёров по доставке пока нет, поэтому кнопка честно показывает «партнёры пока не подключены». Как только партнёр появится — правится только блок `DELIVERY_CONFIG` в `config.js` (см. комментарий там), без изменений в остальном коде.

### Если уже применяли схему базы данных раньше

В `supabase-schema.sql` появился блок «Дополнение v5» (таблица `regulars` для регулярных покупок). Пересоздавать всю схему не нужно — выполните в SQL Editor только этот новый блок в конце файла.

## Что изменилось в этом рефакторинге

- **Убран демо-режим.** Раньше без настроенного Supabase сайт тихо переключался на `localStorage` — это давало ложное ощущение синхронизации (переключатель «Семейный доступ» на самом деле ничего не синхронизировал) и вдвое дублировало логику в `addProduct`/`removeProduct`/`updateProductExpiry`/`logEvent`. Теперь один путь — через Supabase; без настроенных ключей приложение сразу честно показывает баннер ошибки подключения вместо экрана входа.
- **Регулярные покупки теперь общие.** Раньше список лежал в `localStorage` только у того, кто его завёл — остальные члены семьи его не видели. Теперь это таблица `regulars` с RLS и realtime, как и сами продукты (см. «Дополнение v5» в `supabase-schema.sql`).
- **Кнопки блокируются во время запроса.** «Добавить», «Удалить» (съедено/выброшено), «Сохранить срок» и «Следить» (регулярные покупки) теперь используют общий хелпер `withBusy` из `utils.js` — двойной клик/сабмит больше не создаёт дублей в базе.
- **Один файл на ~1750 строк разнесён на модули** (`auth.js`, `products.js`, `history.js`, `recipes.js` — как и просили, плюс несколько маленьких общих модулей `state.js`/`utils.js`/`categories.js`/`config.js`/`delivery.js`, чтобы не дублировать код между ними) через `<script type="module">`.

## Что стоит доработать после MVP

- OCR/сканирование чека или штрихкода для быстрого добавления продуктов.
- Push-уведомления о продуктах, которые вот-вот испортятся.
- Профиль пользователя (смена email, удаление аккаунта).
- Реальная интеграция с партнёром по доставке (сейчас — архитектура-заглушка, см. `DELIVERY_CONFIG`).
